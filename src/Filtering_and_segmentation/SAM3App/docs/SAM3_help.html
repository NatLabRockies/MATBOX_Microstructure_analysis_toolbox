Using the app

  1. Model and device (optional): choose the model, device and precision. The model loads automatically on your first click otherwise.
  2. Segmentation: three ways to prompt SAM, all on the slice shown.
    • Click mode: Refine one object: several clicks shape one object. Left-click includes (green +), right-click or Shift+click excludes (red ×). Then Add object (Enter).
    • Click mode: One object per click: each left-click segments its own object from that single point. In 2D it is added immediately (click through all grains in a row); right-click on an object deletes it, Ctrl+Z removes the newest. In 3D mode each click creates a pending object.
    • Text prompt: type a short noun phrase ("grain", "particle", "cell", "wheel") and press Find all. SAM 3 returns every instance above Text min score as pending objects; right-click removes wrong ones, then Add object (2D) or Propagate (3D). Works best for concepts that look like everyday photos; on unusual imagery (e.g. electron microscopy, MRI) lower Text min score or use clicks.
    Enter / Add objectkeep the current mask, or all pending objects
    Ctrl+Z / Undo pointremove the last click, pending object, or (one-per-click 2D) the newest object
    Esc / Clear pointsdiscard the current clicks and pending objects
    Mouse wheelzoom
    Keep objects in one piece(on by default) removes disconnected fragments from new masks: the piece under the click is kept in 2D, the largest piece for text results and 3D propagation.
    Object listTwo groups: Selected (not propagated) — clicked objects not added yet ("Clicked 1…") and objects added in 2D — and Propagated (3D). Entries are coloured like the overlay, grey when the object is not on the shown slice (Only this slice hides those), and show the object's slice range on the current axis (e.g. "y 125–137" in the XZ view). Clicking an object that is not on the shown slice jumps to the middle of its range. Ctrl+click / Shift+click selects several: Merge selected joins propagated objects; a selected (clicked or 2D) entry merged with a propagated object is tied to it ("→ Object 27") and, when propagated, extends that object. Delete removes the selected objects and clicked entries; Delete all not propagated removes every clicked object and every object added in 2D, Delete all 3D every propagated object (both ask first). Split: select one object, press Split, click one point inside each part (2 or more; any slice), then Apply split or Enter (Esc cancels). The object is cut along its narrowest neck (watershed on the distance to its edge), in 2D or 3D; the first part keeps its number.
    ⟲ 90° / ⟳ 90°rotate the view (display and clicks only; the data and exported labels are not rotated). Useful for long, thin slices.
    The first click on a slice computes that slice's embedding (≈1.5–3 s on a GTX 1080). Later clicks on the same slice take well under a second.
  3. Volumes: pick the view (XY = Z slices, XZ, YZ) and the slice (slider, number field, −/+ for one slice, −−/++ for a tenth of the axis). Then:
    • Current slice mode: objects are 2D masks on that slice (stored in the 3D label volume).
    • 3D volume mode: define the object(s) on one slice (refine clicks, one-per-click, or text prompt), set the slice range (From/To, default: whole volume) and press Propagate. SAM 3's tracker follows all objects forward and backward through the slices in one pass, seeded by their 2D masks. Propagate tracks only the selected (not yet propagated) objects: clicked objects — on any slices, each from its own slice — and objects added in 2D in this view (all of them, or the ones selected in the list); propagated objects are never re-tracked. Clicked objects stay on their slice while you browse. To segment one large object from two ends, click it on a slice near each end (e.g. 75 and 375), select both entries and Merge selected: they are linked ("⇄") and tracked as one object seeded on both slices, so they always share one label. Objects are grouped by their starting slice(s); each group is one run, so clicks on many different slices take proportionally longer. Where objects touch sets the rule for voxels claimed by two objects (between objects tracked together, between passes, and against objects already added): keep existing objects, let the new propagation take over, or leave those voxels empty. Check a few slices, then Add object (each tracked object becomes its own label). Until then the result is drawn in the objects' final colours with a yellow outline meaning "not added yet" (a solid yellow mask is the single object being refined). Propagation can be cancelled; the slices done so far are kept.
    Speed on a GTX 1080: about 1.5 s per slice in float16 (about 2.7 s in float32), almost independent of the number of objects (the image encoder dominates). A 700-slice volume takes about 18 minutes for one object. Several objects are tracked together in passes: each object adds about 0.16 GB of GPU memory and some time (on a GTX 1080: 1 object 1.6 s/slice, 8 objects 2.5 s/slice, 16 objects 3.7 s/slice). Model and device → Objects per pass: Auto picks how many fit in the free GPU memory (shown next to it); Custom lets you set it. Close other GPU programs (e.g. Fiji, games, browsers with many tabs) to fit more. Limit the range to save time. The estimate under Propagate uses the speed of this computer's GPU: measured in earlier propagations (remembered per GPU and precision), otherwise estimated from the image-embedding time of your first click.
  4. Export labels…: a uint16 TIFF (multi-page for volumes; 0 = background, 1..N = objects) or a .mat file with labels, objects (id, voxel count, score, mode, clicks) and the source file name.

Tips for 3D: prompt on a slice where the object is large and clear; propagation works best when the object changes smoothly from slice to slice. If it drifts, propagate a shorter range, or segment from a slice closer to the problem area. XZ/YZ views are shown with square pixels, so anisotropic voxels look stretched or squashed.

Setting up SAM 3 / SAM 3.1 (new computer)

Requirements: Windows or Linux, Python 3.12, git, MATLAB R2026b, an NVIDIA GPU with ≥ 8 GB (recommended; the CPU works but takes about 25 s per image), and a Hugging Face account.

1. Create the project folder and Python environment

cd C:\Users\<you>\Documents\Claude\SAM3App
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip

2. Install PyTorch with CUDA

Pick the CUDA build that supports your GPU:

GPU generationCommand
Pascal/Volta (GTX 10xx, Titan V).venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu126
Turing and newer (RTX 20xx+).venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision --index-url https://download.pytorch.org/whl/cu128
No NVIDIA GPU.venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision (CPU only)

3. Clone and install SAM 3, plus missing dependencies

git clone https://github.com/facebookresearch/sam3.git
.venv\Scripts\python.exe -m pip install -e ./sam3
.venv\Scripts\python.exe -m pip install einops pycocotools psutil "numpy>=1.26,<2" scikit-image "triton-windows>=3.6,<3.7"

triton-windows is only needed on Windows (on Linux, triton comes with PyTorch). Keep numpy below 2 (sam3 requires it).

4. Get access to the weights (gated)

  1. While signed in to Hugging Face, open huggingface.co/facebook/sam3 (and facebook/sam3.1 for SAM 3.1) and request access. Meta reviews requests by hand; it can take from minutes to a day or two. Access is free.
  2. Create a read token at huggingface.co/settings/tokens.
  3. Log in once: .venv\Scripts\hf.exe auth login (paste the token).

The checkpoints (≈3.5 GB each) download automatically the first time a model is loaded, into %USERPROFILE%\.cache\huggingface\hub (once per computer). Model and device → Store weights in app folder copies them into SAM3App\weights (with the SAM License); the app then loads them from there, and a copy of the app folder including weights\ works on another computer without downloading and without a Hugging Face login (step 4 can then be skipped).

5. Put the app files next to the environment

SAM3App\
  SAM3Segmenter.m, SAM3Segmenter.xml   (the app)
  python\sam3_backend.py               (bridge used by the app)
  docs\help.html, docs\about.html
  .venv\   sam3\

Start MATLAB, cd into SAM3App and run SAM3Segmenter. The app configures pyenv for the .venv Python in OutOfProcess mode (MATLAB remembers this setting). To return to another Python: terminate(pyenv); pyenv(Version="path\to\python.exe").

Troubleshooting

Why no uint8 / uint16 precision?Precision is the number format of the neural network's arithmetic, not of your data. Every image (uint8 or uint16) is converted to 8 bits and then to normalised floating point before SAM sees it (SAM was trained on 8-bit images). Integer ("int8") inference is not supported by this code and would not speed up a Pascal GPU; float16 is the fast choice.
pip: "certificate verify failed"The network (often a corporate proxy) re-signs HTTPS traffic with a certificate that Windows trusts but pip's own list does not. Add --use-feature=truststore to each pip install command so pip uses the Windows certificate store, starting with .venv\Scripts\python.exe -m pip install --upgrade pip --use-feature=truststore (pip 24.2 and newer do this by default). If it still fails, ask IT for the proxy's root certificate (.pem) and run .venv\Scripts\python.exe -m pip config set global.cert C:\path\to\root.pem.
"Could not access gated repo"Access not approved yet, or not logged in: check .venv\Scripts\hf.exe auth whoami.
Very slow, or more than 8 GB of GPU memoryOn GPUs older than Ampere, keep Precision on Auto (float16). SAM 3.1 needs about 45 s and 9.5 GB per image on a GTX 1080; use SAM 3.
"MATLAB is running another Python in-process"Restart MATLAB, then start the app before using any other Python code.
'sam3' resolved to a folderRun terminate(pyenv) and start the app again.
SAM 3.1 resultsSAM 3.1 weights are only available through the repo's video predictor. For single images it tends to return the whole object and ignore exclude clicks; it is kept as an experimental option.
